## 관찰

- 덴트류가 11종/17종으로 압도적 다수 — 대부분의 학습 데이터가 찌그러짐에 쏠려 있음
- 상위 6개 클래스(범퍼·도어·보닛류)가 전체 인스턴스의 약 70%를 차지 — 클래스 불균형이 여전히 큼 (증강으로 일부 완화했지만 Bodypanel-Dent 203개는 여전히 최소 기준선 200개 근처)
- 손상 "종류"(스크래치 vs 찌그러짐 vs 파손) 구분은 없고, "부위 + 상태"가 묶인 클래스 체계임. 별도의 스크래치 클래스는 없고 덴트/파손 위주로 구성됨

## 참고

이 4개 카테고리(덴트/유리/램프/미러) 구분은 RAG 챗봇 문서 설계 시 문서 그룹핑 기준으로도 활용 가능함.

Bodypanel-Dent 클래스는 family가 단 4개뿐입니다(train 3 / valid 0 / test 1). 즉 REVIEW.md에서 봤던 "203개 인스턴스"는 사실상 원본 사진 3~4장을 증강으로 200개까지 부풀린 것이라, 이 클래스는 모델이 실제로는 몇 장 안 되는 사진의 변형만 외우고 있는 셈입니다. valid에 0장 배정된 것도 그 여파입니다. 이건 재분할 알고리즘 문제라기보다 원본 데이터 자체가 이 클래스에 한해 심각하게 부족하다는 신호라, 나중에 이 클래스만 별도로 데이터 보강이 필요할 수 있습니다.
